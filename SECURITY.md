# Security Policy

## Supported version

Security reports are accepted for the current code on the `main` branch and the live site at https://isitfree.webline.cloud/.

## Reporting a vulnerability

Please do not publish exploitable security details in a public issue.

Use GitHub's **Report a vulnerability** option on the repository's **Security** tab, when available, to send a private vulnerability report. If that option is unavailable, contact the maintainer through their GitHub profile: https://github.com/nav-neet-kumar.

Include a description of the issue, affected page or component, steps to reproduce, potential impact, and any safe proof-of-concept details. Please avoid accessing, modifying, or exposing other people's data while investigating.

## What to expect

The maintainer will review the report, may ask for more details, and will work on assessing and addressing a valid issue. Please allow reasonable time for investigation before public disclosure. There is no guaranteed response or remediation timeline.

## Scope and safe harbor

Only test systems you own or have explicit permission to test. Do not attempt denial of service, social engineering, credential theft, or destructive testing. This policy is not permission to violate laws or third-party terms.
